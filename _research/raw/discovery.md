## Method / tooling note (important for how much to trust each line)
- Primary verified sources used: **Apple App Store lookup/search API** (`_research/itunes.py`, official sellerName / releaseDate / ratingCount / full description) and **direct HTTP fetch of the official site** (`_research/fetch.py` / `idcheck.py`, keyword counts recorded).
- Bing via `search.py` returns a **stale cached result set** (same ~10 results regardless of query) — not usable for discovery; recorded but not relied on.
- DuckDuckGo `lite` worked for a first burst of queries (results recorded below) and then began serving a **bot challenge** ("Select all squares containing a duck", HTTP 202). Other engines (Mojeek, public searx instances, startpage) were 429/challenge/blocked. So later web-only discovery was done by **following vendor sites themselves** (their `/llms.txt`, `/alternatives`, sitemaps) plus App Store sweeps across US/GB/CA/AU/DE/FR/ES storefronts.
- Wayback CDX (`web.archive.org`) used only as an age hint (`matchType=domain` = earliest capture of anything under that domain, incl. re-registered old domains).
- Nothing below is invented: every DIRECT/ADJACENT line is backed by either a live fetch or an App Store record. Anything that could not be verified is in **Candidates needing verification**.
